# План улучшений фронтенда RanobeDays

## 1) Что сейчас можно улучшить (краткий аудит)

### Архитектура и поддерживаемость
- В `src/views/HomeView.vue` зашиты демо-данные карточек прямо в шаблоне. Это усложнит масштабирование и повторное использование.
- В `src/components/layout/Header.vue` смешаны UI, мок-стейт (`isLoggedIn`, `hasNotifications`) и бизнес-логика. Нужен вынос в store/composable.
- Используется смесь Tailwind и большого объема scoped CSS без единой дизайн-системы (токены есть в `src/assets/_variables.css`, но используются непоследовательно).

### Роутинг
- В `src/router/index.js` объявлен только маршрут `/`, но в `Header.vue` есть ссылки на `/catalog`, `/notifications`, `/favorites`, `/profile`, `/login`, `/novel/:slug`. Это ведет к 404/пустым переходам.
- Нет route-level lazy loading.

### Доступность (a11y)
- У интерактивных элементов фокус-стили и семантика частично реализованы, но нет системной проверки контрастности/клавиатурной навигации.
- Есть интерактивные элементы с `router-link` на `#` (`NovelCardWithTags`), что ухудшает UX и доступность.

### Производительность
- В `vite.config.js` включен polling watch (`usePolling: true`), что может сильно нагружать CPU в dev без необходимости.
- Нет стратегии оптимизации загрузки страниц/компонентов (code splitting по роутам, prefetch и т.д.).
- Tailwind-конфиг в проекте почти не используется для токенов (много hex в компонентах).

### Качество кода и DX
- Нет линтинга (`eslint`) и style-linting, нет pre-commit хуков.
- Нет тестов (unit/component/e2e).
- В `package.json` одновременно `bun.lock` и `package-lock.json` — не определена единая стратегия пакетного менеджера.
- Подключены Google Fonts через CSS `@import` (`src/assets/_fonts.css`) — это хуже для производительности, чем `<link rel="preconnect">` + `<link href=...>` в `index.html`.

## 2) Приоритетный план (roadmap)

## Этап 1 — Стабильность и базовая гигиена (высокий приоритет)
1. Привести роутинг в соответствие UI:
   - добавить отсутствующие маршруты;
   - добавить `NotFound` страницу;
   - исправить временные ссылки (`#`) на корректные пути или disabled-состояния.
2. Вынести мок-данные из `HomeView.vue` в отдельный слой данных (`src/mocks/novels.js` или `src/services`).
3. Убрать polling в `vite.config.js` (включать только по env-флагу при реальной необходимости).
4. Определить один пакетный менеджер и удалить лишний lock-файл.

Ожидаемый результат: исчезают битые переходы, снижается риск регрессий, проще развивать приложение.

## Этап 2 — Архитектура состояния и композиция (высокий приоритет)
1. Подключить Pinia и перенести пользовательский/навигационный стейт из `Header.vue` в store.
2. Вынести поисковую логику в composable (`useSearch`) и унифицировать API `SearchBar`:
   - оставить события (`update:modelValue`, `search`),
   - убрать `onSearch` проп-функцию как дублирующий канал.
3. Разделить `Header.vue` на более мелкие компоненты (desktop nav, mobile nav, user controls).

Ожидаемый результат: чище ответственность компонентов, меньше связанности, проще тестировать.

## Этап 3 — Дизайн-система и единообразие UI (средний приоритет)
1. Превратить `src/assets/_variables.css` в источник дизайн-токенов и использовать их в компонентах вместо жестких hex.
2. Расширить Tailwind theme токенами (colors, spacing, radius, shadows, breakpoints) и переиспользовать utility-классы.
3. Зафиксировать UI-конвенции:
   - naming props/events;
   - состояние `loading/empty/error` для списков;
   - единый подход к hover/focus/active.

Ожидаемый результат: консистентный визуал, быстрее разработка новых экранов.

## Этап 4 — Доступность и UX (средний приоритет)
1. Пройтись по всем интерактивным элементам: корректные `aria-*`, видимый focus-ring, таб-навигация.
2. Проверить контрастность цветовых пар и привести к WCAG AA.
3. Добавить состояния:
   - skeleton/empty/error для лент;
   - user-friendly fallback для отсутствующих картинок (уже частично есть).

Ожидаемый результат: интерфейс доступнее и предсказуемее для пользователей.

## Этап 5 — Производительность и поставка (средний приоритет)
1. Сделать lazy loading роутов (`() => import(...)`).
2. Оптимизировать шрифты:
   - перенести подключение в `index.html` с `preconnect`;
   - сократить наборы/начертания.
3. Добавить базовый анализ бандла (`vite-bundle-visualizer` или аналог) и бюджет на размер чанков.

Ожидаемый результат: быстрее первый рендер и навигация между экранами.

## Этап 6 — Качество и CI (высокий приоритет)
1. Добавить ESLint (+ `eslint-plugin-vue`) и скрипты `lint`, `lint:fix`.
2. Добавить тестовую пирамиду:
   - unit/component: Vitest + Vue Test Utils;
   - e2e smoke: Playwright.
3. Добавить Husky + lint-staged (pre-commit).
4. Настроить CI (GitHub Actions): `install -> lint -> test -> build`.

Ожидаемый результат: раннее обнаружение ошибок и стабильные поставки.

## 4) Definition of Done для плана
- Нет битых роутов и переходов.
- Все новые PR проходят `lint`, `test`, `build` в CI.
- Ключевые компоненты (`Header`, `SearchBar`, карточки) покрыты тестами.
- Дизайн-токены используются централизованно.
- Lighthouse (mobile) для главной страницы: Performance >= 85, Accessibility >= 90.
